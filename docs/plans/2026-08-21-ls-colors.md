## GNU is the spec

Verified against current coreutils `src/ls.c` (`parse_ls_color`,
`get_color_indicator`):

- Unset or empty `LS_COLORS`: do not parse; keep today's
  vibeutils palette (GNU would consult TERM/COLORTERM; we
  already have that via `Style` / `--color`).
- Set and **valid**: overlay keys onto the existing palette.
  Keys not named in the string keep compiled/vibeutils
  defaults (GNU overwrites `color_indicator[i]` in place).
- Set and **invalid** (unrecognized two-letter prefix, or
  parse FAIL): print `unrecognized prefix: XX` and/or
  `unparsable value for LS_COLORS environment variable` on
  stderr, then **disable color** for the invocation
  (`print_with_color = false`). Do not keep a half-parsed
  table.
- Suffix `*` entries are **prepended**. Later definition
  overrides earlier. Match is the first list hit whose
  suffix equals the name tail. GNU is first-hit after
  prepend (last-listed wins). **Not** longest-wins. This
  slice is case-sensitive (GNU's optional exact-match
  postpass is out of scope; do not add a case-insensitive
  fallback).
- Suffixes run **only if** the file is still classified
  `C_FILE`. Type codes (`di`, `ex`, `su`, …) beat globs.
- Empty / `0` / `00` SGR means "not colored" for that key
  (`is_colored` false).
- `38;2;…` is valid SGR. Pass the value through; do not
  strip truecolor sequences.
- Control keys `lc`/`rc`/`ec`/`rs`: parse. Apply `lc` + seq
  + `rc` (or `ec` if set) around the name. Defaults: `lc` is
  ESC `[`, `rc` is `m`, `rs` is `0`. `ln=target` is **out of
  scope** this slice (keep coloring the symlink as `ln`).

## In scope

`src/common/ls_colors.zig` (force-import, `common.ls_colors`):

- Pure `parse(allocator, text) !Table` — never `setenv`.
- `ls_colors_entries_max: u32 = 1024` (dircolors defaults
  are ~200; themes exceed 256). Bound the loop. Extra
  pairs after the cap are a parse FAIL (`unparsable
  value for LS_COLORS`). Do not silently drop. Do not
  ignore overflow.
- Two asserts per function, ≤70 lines, no recursion.

`src/ls/display.zig` **and** `src/ls/formatter.zig`
(`getFileColor` and `getColorForKind` / name write path):

- Classify with GNU precedence where `Entry.stat` has mode:
  `su`/`sg`/`ex` for files; `tw`/`ow`/`st` for dirs; `di`,
  `ln`, `so`, `pi`, `bd`, `cd`, `fi`; `or`/`mi` for dangling
  / missing if we already detect that. Codes we cannot
  classify yet are parsed but unused (named in the plan:
  `do` door, `ca` capability, `mh` multi-hardlink unless
  nlink is already on the entry).
- When a table is present and the key is colored, emit
  `lc`+SGR+`rc` around the name, then reset via `rs` / the
  existing `style.reset()` so `color_mode != .none` stays
  the gate.
- `--color=never`, `NO_COLOR`, `TERM=dumb` still win.

## Tests (failing first, separate test-writer)

Names without `#`. Never `setenv`. Pure parser takes a
string. Stub so RED is an assertion.

Parser:

1. Empty string → overlay-empty (lookups miss; caller keeps
   defaults).
2. `di=01;34` → di is `01;34`.
3. `*.zip=01;31:di=01;34` → both keys.
4. **Last listed suffix wins** — `*.gz=01;31:*.tar.gz=01;32`
   then `foo.tar.gz` matches `*.tar.gz` only because it was
   listed last **and** is a suffix; also
   `*.tar.gz=01;32:*.gz=01;31` → `foo.tar.gz` matches
   `*.gz` (last listed that suffixes). Not longest-wins.
5. Type beats glob — a directory named `foo.zip` uses `di`,
   not `*.zip` (ls-level test).
6. Unrecognized prefix `zz=01` → parse error (not a skipped
   pair).
7. Empty value `ex=` or `ex=00` → that key is not colored.

ls (overrides, `--color=always`, scrub `NO_COLOR`, pin
`TERM=xterm-256color`):

8. `LS_COLORS=di=01;34` directory name contains `01;34` and
   reset.
9. `--color=never` plus `LS_COLORS` → no CSI.
10. Unset `LS_COLORS` → today's bright-blue directory.
11. Invalid `LS_COLORS=zz=01` → stderr contains
    `unparsable value for LS_COLORS` (and/or `unrecognized
    prefix`); names have no CSI.
12. `getColorForKind` / `-l` symlink-target path also uses
    the table (not only `getFileColor`).
